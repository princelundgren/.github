# Contributing

Thanks for helping. Taking part means following the [Code of Conduct](https://github.com/princelundgren/.github/blob/main/CODE_OF_CONDUCT.md), and a
security problem goes through the [security policy](https://github.com/princelundgren/.github/blob/main/SECURITY.md), never a public issue.

## Issues

- **A bug:** use the bug report form, with the steps that show it and the versions you ran
- **A new feature:** open an issue first, before writing code. Each project keeps to a narrow job,
  so agreeing on the idea saves you a pull request that can't be merged

## Pull requests

1. **One change per pull request**, small enough to review in one sitting
2. **The tests pass**, with new tests for what you change: the project's README says how to run
   them
3. **Say what it changes and why, in your own words**: the template asks for it, and a generated
   summary doesn't tell the maintainer why you want the change
4. **Commits are signed** where the repository requires it: GitHub's docs explain
   [signing commits](https://docs.github.com/en/authentication/managing-commit-signature-verification/signing-commits)

A pull request from a fork waits for the maintainer to approve its CI run the first time.
